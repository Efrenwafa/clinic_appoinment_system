Appendix A: System Proposal Deliverable A
Proposal Item Specification & Details
System Name Secure Clinic Appointment and Monitoring System
Who Uses It Patients: Register securely, verify email via 6-digit OTP, log in using two-step authentication, request clinic appointments, view only their own appointment history/status, use self-service password reset, and log out securely.

Clinic Administrator: Authenticates through a protected login flow with OTP, reviews and manages clinic appointment requests, updates appointment statuses, and accesses the protected security monitoring dashboard to inspect real-time security events, lockout status, IP blocking, and automated monitoring flags.
What It Stores 1. Patient Account & Identity: ID Number (format xxxx-xxxx, primary key), Full Name (First, Middle, Family, Extension), Birthdate, Age, Address (Purok/Street, Barangay, City, Province, Country, ZIP), Email Address, and Username.
2. Security Credentials: Password hashes (password_hash with BCRYPT/Argon2id), hashed authentication answers, hashed OTP codes (purpose, expiry, attempt counter), and password history (hashes of last 3 passwords).
3. Appointment Information: Appointment date/time, department, patient type, reason, status, and AES-256 encrypted contact number.
4. Security Logs: Append-only activity logs (event type, username typed, user ID, IP address, user-agent, details, timestamp), failed logins, lockout records, IP blocks, and security flags.
Why Accounts Need Protecting The system stores personal information and clinic consultation records governed by the Philippine Data Privacy Act of 2012 (Republic Act No. 10173). Protecting accounts prevents unauthorized disclosure of health appointments, identity theft, unauthorized cancellation or tampering with medical consultations, credential stuffing attacks, and administrative dashboard takeover.
Sensitive Field to Encrypt (Protection 13) Patient Contact Number. Encrypted at rest in MySQL using AES-256 (via PHP OpenSSL openssl_encrypt() with a securely generated random IV). Decrypted strictly to display to its legitimate owner. The AES key is stored outside Git in config.php. Passwords, answers, and OTPs are one-way hashed.
