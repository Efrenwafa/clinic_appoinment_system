3 Step-by-Step Workflow Walkthrough

Scenario A: Patient Registration & Email OTP Verification

  1. Navigate to register.php.
  2. Complete the registration form using valid Title Case inputs. Note that age is calculated dynamically from birthdate.
  3. Fill the 4 clinic fields: Contact Number (09XXXXXXXXX), Patient Type, Clinic Department, and Emergency Contact.
  4. Answer the 3 assigned security questions (Q2, Q5, Q7), solve the image CAPTCHA, and check the RA 10173 consent box.
  5. Submit the form: the server validates all inputs, hashes passwords/answers with Bcrypt, encrypts the contact number with AES-256, and dispatches a 6-digit OTP (valid for 4 minutes).
  6. On verify_otp.php, enter the 6-digit OTP from your Gmail inbox. Upon verification, the account is activated.

Scenario B: Patient Login & Appointment Booking

  1. Go to login.php, enter username patient_juan, password JuanPassword123!, and solve the CAPTCHA.
  2. Enter the 6-digit Login OTP sent to your email. The system regenerates the session ID and redirects to appointments.php.
  3. Show Decrypted Phone: Demonstrate that the contact number 09876543210 is legibly decrypted at runtime, but stored as ciphertext in MySQL.
  4. Book Consultation: Select department, appointment date/time, enter reason, and submit. The appointment appears as Pending.
  5. Anti-IDOR Defense: Explain that appointments are isolated by WHERE patient_id = :session_user_id. Patients cannot access other records.

Scenario C: Demonstrating Progressive Lockout & IP Protection

  1. Open an Incognito window to login.php.
  2. Enter username patient_juan and intentionally enter an incorrect password 3 consecutive times.
  3. Failure 3 (Lockout Tier 1): The account locks for 24 seconds ($15 + D_1 = 15 + 9$). A live countdown timer disables the submit button and registration link. A Security Lockout Alert email arrives in your inbox.
  4. Show that refreshing the browser or clearing cookies cannot bypass the lockout, as the server enforces it in MySQL.
  5. Explain Tier 2 (6 failures = 48s) and Tier 3 (9 failures = 96s), as well as IP-level blocking after 9 failures within 10 minutes.

Scenario D: Account Recovery & Password History Prevention

  1. Click "Forgot Password?" on login.php, enter patient_maria, and solve the CAPTCHA.
  2. Select Question 2, enter answer bantay, and submit to receive a Password Reset OTP.
  3. Enter the OTP to access the token-protected change_password.php?token=... page.
  4. Test History Refusal: Attempt to set the password to Maria's old password: MariaPassword123!. The server blocks it with: "You cannot reuse any of your last 3 passwords."
  5. Enter a new strong password: NewMariaSecret!2026. The password updates, and a confirmation email is dispatched.

Scenario E: Administrator Security Monitoring Dashboard

  1. Log in as admin_monitor / AdminPassword123! and verify with Login OTP.
  2. Access admin_dashboard.php.
  3. Show Summary Cards: Failed Logins Today, Active Lockouts, Active IP Blocks, Flagged Suspicious Events.
  4. Show 24-Hour Bar Chart: Hourly visualization of failed login attempts.
  5. Show Immutable Audit Logs (Protection S11): Point out that the dashboard has zero edit or delete buttons, ensuring forensic integrity.
