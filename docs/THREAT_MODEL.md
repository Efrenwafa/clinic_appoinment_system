### Threat Model Matrix (Section 12 Protections Mapped to CIA Triad)

| # | Protection | Threat | Vulnerability Exploited | Countermeasure Implemented | CIA | How It Was Tested |
| :-: | :--- | :--- | :--- | :--- | :-: | :--- |
| **1** | **SQL Injection** | Attacker injects malicious SQL statements via input fields to bypass authentication or dump database. | Unescaped string concatenation in dynamic SQL queries. | **PDO prepared statements with parameter binding for EVERY query.** Emulated prepares disabled (`PDO::ATTR_EMULATE_PREPARES => false`). | **C, I** | Submitted `' OR '1'='1` in login and registration fields. Rejected with 0 matching rows and zero SQL syntax errors. |
| **2** | **Cross-Site Scripting (XSS)** | Attacker injects malicious JavaScript into user-controlled fields (e.g. username) to steal admin cookies on dashboard. | Displaying raw user input directly into HTML response. | **Context-aware output encoding with `htmlspecialchars($v, ENT_QUOTES \| ENT_SUBSTITUTE, 'UTF-8')`** on all output, including log tables. | **I, C** | Input `<script>alert(1)</script>` as username during failed login; opened security dashboard; browser rendered literal string `&lt;script&gt;` with zero script execution. |
| **3** | **CSRF** | Attacker tricks authenticated patient or admin into submitting unauthorized requests via third-party site. | Browser automatically sending session cookies with cross-site POST requests. | **Cryptographically secure random CSRF token (`bin2hex(random_bytes(32))`)** embedded in all state-changing forms and validated on server. | **I** | Deleted `csrf_token` input using browser developer tools and submitted form; server rejected request with `CSRF_REJECTED` audit log. |
| **4** | **Username Enumeration** | Attacker discovers valid patient/admin usernames by analyzing distinct error messages. | Distinct error messages like "Username not found" vs "Wrong password". | **Identical generic message: `"Invalid username or password."`** in both Log-in and Forgot Password flows. | **C** | Submitted valid username with wrong password, then nonexistent username; compared side-by-side; both returned the exact same error message. |
| **5** | **IP Blocking** | Distributed automated bots perform high-volume credential guessing attacks across many usernames. | Unlimited login attempts from a single machine/IP address. | **Server-side IP tracking in `ip_blocks` table.** Blocks IP address for 10 minutes if 9 failures occur within 10 minutes ($8 + D_2 = 9$). | **A, C** | Simulated 9 consecutive failed logins from `127.0.0.1`; on 9th failure, IP was blocked for 600 seconds with `IP_BLOCKED` event logged. |
| **6** | **Session Hardening** | Attacker intercepts session cookie via packet sniffing, XSS, or reuses session after victim logs out. | Predictable session IDs, lack of cookie protection flags, or orphaned active sessions. | **`session_regenerate_id(true)` upon login**, `HttpOnly`, `SameSite=Lax`, and seeded **9-minute idle timeout** ($5 + (9 \pmod 5) = 9$). Complete cookie & server destruction on logout with no-cache headers. | **C, I** | Verified cookies contain `HttpOnly` and `SameSite`; logged out and clicked browser back button; cached page was refused via HTTP `no-store` headers. |
| **7** | **Password History** | Compromised former password is reused by patient, enabling persistent attacker access. | System allowing user to cycle back to a compromised recent password. | **`password_history` table retains hashes of the last 3 passwords.** Compares candidates using `password_verify()` and refuses reuse. | **C, I** | Attempted to change password to the current password; server rejected with exact message: `"You cannot reuse a recent password."` |
| **8** | **Honeypot** | Automated spambots submit registration forms programmatically at high speed. | Web spiders and scraping bots indiscriminately filling all visible and invisible input tags. | **Invisible form field `clinic_partner_website` (hidden via CSS).** If filled with any data, request is silently dropped without creating records. | **A, I** | Filled hidden honeypot field using browser DevTools and submitted; server refused registration silently without saving to database. |
| **9** | **Activity Log** | Malicious actions occur undetected without an audit trail for forensic investigation. | Absence of persistent security event logging. | **Append-only `activity_logs` table** capturing all 15 course event types with timestamp, IP, user agent, typed username, and details. | **I, C** | Performed login, lockout, and password change; inspected `activity_logs`; every event was captured with exact metadata. |
| **10** | **Error Handling** | Attacker triggers server exceptions to view internal database schemas and file paths. | PHP displaying uncaught exceptions, stack traces, and SQL syntax errors to the client. | **`ini_set('display_errors', '0')` and custom try-catch blocks.** Real errors are written exclusively to `logs/error.log` outside web access. | **C** | Submitted malformed database inputs; user received a generic error message while detailed PDO exception was routed to `logs/error.log`. |
| **11** | **Secrets Management** | Database passwords, SMTP credentials, and encryption keys leaked to public Git repository. | Hardcoding sensitive passwords directly in tracked source files. | **Credentials isolated in `config.php`, strictly excluded by `.gitignore`.** Only `config.sample.php` with placeholder values is committed. | **C** | Ran `git log -S` for real passwords; zero secrets found in repository commit history. `config.php` verified ignored. |
| **12** | **Security Headers** | Clickjacking (embedding site in malicious iframe) and MIME-type sniffing attacks. | Missing HTTP security policy headers in web server responses. | **Mandatory headers sent on every response:** `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`. | **I, C** | Inspected browser Network tab headers; verified `X-Frame-Options: DENY` and `X-Content-Type-Options: nosniff` present on all responses. |
| **13** | **Encryption at Rest** | Database compromise or physical storage theft exposes patient mobile contact numbers. | Storing sensitive personal contact numbers in readable plaintext format. | **AES-256-CBC encryption at rest** via PHP OpenSSL with a cryptographically secure random 16-byte IV (`random_bytes(16)`). Decrypted only when displaying to owner. | **C** | Queried `users` table directly in MySQL; `contact_number_encrypted` displays unintelligible base64 ciphertext; decrypted only within authenticated session. |
